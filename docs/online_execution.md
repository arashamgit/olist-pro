# اجرای آنلاین پروژه (بدون نصب روی سیستم شخصی)

<div dir="rtl" align="right">

این سند سه راه اجرای کامل پروژه از روی گیت‌هاب را توضیح می‌دهد. هیچ‌کدام نیازی به نصب
Python روی رایانه شخصی ندارند و برای سه عضو تیم و ارائه به استاد یکسان کار می‌کنند.

## ۱. GitHub Codespaces (توصیه‌شده برای اجرای واقعی)

مخزن یک `.devcontainer` دارد که محیط پایتون، وابستگی‌های قفل‌شده و کرنل `olist-pro` را
خودکار آماده می‌کند.

۱. روی نشان **Open in GitHub Codespaces** در `README.md` بزن (یا از دکمه سبز Code →
   Codespaces → Create codespace on main).
۲. یک ماشین با ۴ هسته انتخاب کن (در فایل `devcontainer.json` به‌صورت پیش‌فرض درخواست
   شده است؛ برای داده ۱۲۰ مگابایتی، ۲ هسته کند است).
۳. در ترمینال Codespaces:

```bash
python scripts/validate_data.py   # دروازه کیفیت داده: ۲۲ بررسی
python scripts/run_all.py         # خط لوله + ۱۳ نوتبوک + گزارش + ۵۶ آزمون
```

خروجی‌ها در `reports/` ساخته می‌شوند: ۵۸ جدول، ۳۱ نمودار، `metrics.json` و گزارش
فارسی Markdown و PDF. نوتبوک‌ها هم با خروجی‌های واقعی ذخیره می‌شوند.

سهمیه رایگان Codespaces برای حساب شخصی در صفحه Billing حساب قابل مشاهده است؛ برای
صرفه‌جویی، بعد از پایان کار Codespace را Stop کن.

## ۲. Binder (لینک اجرای بدون حساب)

`binder/requirements.txt` محیط را می‌سازد و `binder/postBuild` کرنل پروژه را ثبت می‌کند.
این فایل باید همان قفل‌های `requirements.txt` ریشه را داشته باشد، چون repo2docker
به‌محض وجود پوشه `binder/` فقط داخل همان پوشه را می‌گردد.
با یک لینک، JupyterLab باز می‌شود و هر نوتبوکی از `notebooks/` اجرا می‌شود:

```text
https://mybinder.org/v2/gh/arashamgit/olist-pro/HEAD
```

محدودیت‌ها: ساخت اولین جلسه چند دقیقه طول می‌کشد، جلسه موقت است (تغییرات پایدار
نمی‌ماند) و منابع از Codespaces کمتر است. برای نمایش سریع به هم‌تیمی مناسب است.

## ۳. GitHub Actions (اجرای خودکار و دانلود خروجی)

دو ورک‌فلو در `.github/workflows/` هست:

| ورک‌فلو | زمان اجرا | کار |
| :--- | :--- | :--- |
| `ci.yml` | هر push و هر Pull Request | دروازه کیفیت داده (۲۲ بررسی) + ۵۶ آزمون |
| `analysis.yml` | دستی (تب Actions → Full analysis run → Run workflow) | کل خط لوله + نوتبوک‌ها + گزارش + ساخت ZIP؛ خروجی‌ها به‌عنوان Artifact قابل دانلود است |
| `pages.yml` | هر push روی `main` و `release/**` | بازساخت خروجی‌ها و انتشار سایت نتایج |

برای فعال‌کردن انتشار سایت، یک‌بار در **Settings → Pages** گزینه **Source** را روی
**GitHub Actions** بگذار؛ بعد از آن آدرس سایت در بخش Pages نمایش داده می‌شود.

## ۴. سایت نتایج (GitHub Pages)

`scripts/build_site.py` یک صفحه راست‌به‌چپ از داده واقعی می‌سازد: کارت‌های شاخص‌ها،
پنج یافته مهم، نمودارها با توضیح، جدول‌های تحلیل، گزارش PDF و لینک نوتبوک‌ها.

```bash
python scripts/build_site.py --output site
```

خروجی در `site/` ساخته می‌شود و کاملاً ایستا است؛ اجرای پایتون روی سرور لازم ندارد.

## ترتیب پیشنهادی برای ارائه

۱. سایت نتایج را نشان بده (تصویر کلی و یافته‌ها).
۲. Codespaces را باز کن و `python scripts/run_all.py` را زنده اجرا کن (بازتولید کامل).
۳. در تب Actions خروجی اجرای خودکار و Artifactها را نشان بده.
۴. گزارش PDF را برای بحث مدیریتی باز کن.

## نکته‌های فنی

- داده خام در `data/raw/` داخل مخزن است؛ به همین دلیل محیط آنلاین به دانلود جداگانه
  نیاز ندارد. فایل `olist_geolocation_dataset.csv` با ۵۸.۴۴ مگابایت بزرگ‌ترین فایل
  مخزن است و گیت‌هاب برای آن هشدار اندازه می‌دهد (بدون خطا).
- مسیرهای پروژه نسبی هستند و از `PROJECT_ROOT` مشتق می‌شوند، پس در Codespaces،
  Binder و Actions یکسان کار می‌کنند.
- برای اجرای نوتبوک‌ها باید کرنل `olist-pro` ثبت شده باشد؛ این کار در
  `devcontainer.json` و `binder/postBuild` خودکار انجام می‌شود.
